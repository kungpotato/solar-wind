## Business direction (v3.0) — read before changing anything

- **Solo dev, revenue-first, no licenses.** Phase A = crypto DCA (USDC → WETH / cbBTC on Base via Uniswap v3 / Aerodrome), non-securities, permissionless, 24/7. Revenue = **on-chain protocol fee (25 bps) only** — no subscription (AI is BYO/optional), no performance/AUM fee. Company is formed only when revenue ≥ ~$1k/month; audits are gated on TVL ($100k → contest, $1M → round 2).
- **Legal posture = structure, not size** (01 หัวข้อ 1.1): open-source non-upgradeable contracts, self-host option, user-defined rules, no recommendations/default portfolio, no custody, factual notifications, ToS/risk disclosure, sanctions geo-block. Never add features that look like advice, managed portfolios, or per-AUM fees.
- **Phase B (later)**: tokenized US stocks via a licensed partner/TSV under the SEC Innovation Exemption (2026-09-17 → 2031-09-17). The `EligibilityProvider`, venue-hours rules and `TSVPoolAdapter` are designed but **disabled in Phase A**; do not wire them into Phase A flows.
- **Channels**: MetaMask/WalletConnect first, Telegram bot for alerts/NL/deep links, email secondary. **No LINE.** Passkey smart account (ERC-4337) at T0.

## What the system is

Users set their own DCA rules and the agent buys crypto (Phase A: WETH/cbBTC on Base) from USDC on a weekly period, executed gaslessly by our solver, with the user's key never leaving their wallet and the agent's authority bounded by on-chain caveats in `RwaDcaSettlement.sol`. The workshop's USDY is only a mock token. Phase B swaps the adapter for tokenized US stocks via a licensed partner. The user's private key never leaves their wallet; the agent's authority is bounded by on-chain caveats in `RwaDcaSettlement.sol`. Solvers pay gas (gasless for users).

## Non-negotiable design principles (from the doc)

Any code added to this repo must respect these — they are the security model, not style preferences:

- **Chain is the enforcer.** Every rule protecting user funds (per-period budget, lifetime cap, token pair allowlist, recipient == user, expiry, single-use nonce) lives in the settlement contract. Off-chain services are assumed compromisable; max blast radius = one period budget per user + the solver hot wallet balance.
- **LLM is BYO and advisory only, never in the decision path (ADR-005).** The platform pays for no tokens. Tier A (default): the user's key stays in the browser and calls the provider directly. Tier B (opt-in, 01 หัวข้อ 8.1): the key is stored envelope-encrypted (per-user DEK wrapped by OCI Vault KEK `sw-userkeys-kek`) and used only by `core/llmproxy` via the egress allowlist, with scopes, per-user budgets, usage audit, anomaly auto-suspend and crypto-shred on delete. Never log or persist a plaintext key. NL → `StrategyRules` runs client-side with the user's own provider key; the server only validates the resulting JSON (schema + on-chain bounds, user confirms). Macro/news signal is a deterministic indicator table from free feeds (FRED, on-chain APY, price drawdowns), not an LLM. Explanations are templates from `reasons[]`. Do not add LLM API calls to `core`/`exec`. The **Decision Engine is a pure, deterministic function** `decide(rules, snapshot, delegationState) → Decision {BUY|POSTPONE|SKIP, amountIn, minAmountOut, deadline, reasons[]}` with no I/O, replayable from `(rulesVersion, snapshotHash)`. Do not put LLM calls or network I/O in it.
- **Stale data → SKIP, never default BUY.** `MarketSnapshot` is immutable, content-addressed (sha256), and carries staleness info.
- **Signer is isolated.** Only the Decision Engine and Solver may talk to the Intent Signer (gRPC + mTLS). The signer enforces an EIP-712 typed-data allowlist (domain, verifyingContract, token pair, amount ≤ hard cap). No fallback keys.
- **Idempotent everywhere.** Exactly-once settlement comes from `usedNonces` on-chain; infra is at-least-once. Nonce = `keccak(user, periodStart, attempt)`. One in-flight intent per user (`pg_advisory_xact_lock` + DB unique on `(user, period_start)`). No Redis/Kafka/Temporal in Phase 1: Postgres is the only stateful service (job queue via `FOR UPDATE SKIP LOCKED`, transactional outbox).
- **Finality-aware indexing.** States are `pending → safe → finalized`; users are notified only on finalized. Reorgs roll state back to pending.
- **User `revokeAgent` must always work**, even when `pauseSettle()` is active (non-custodial guarantee). Core settlement contract is non-upgradeable; registries/fee module are Ownable via Timelock + Safe.

## Planned architecture (C4 L2 containers)

Flow per DCA cycle (a `dca_cycle(user)` job in the Postgres queue, state machine on `intents.status`):
Perception → Decision Engine → Intent Signer → Solver (route + `eth_call` simulate + private mempool submit) → `settle()` on-chain → Indexer (finality + reconciliation) → Notifier (outbox pattern).

Three-key model: **user master key** (wallet; signs only `approve`/`configureDcaAgent`/`revokeAgent`), **agent session key** (signer enclave; signs intents only; rotated every 90 days), **solver hot wallet** (pays gas; capped balance; refilled from Treasury Safe with human approval).
